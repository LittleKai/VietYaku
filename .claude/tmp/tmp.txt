### 1. Bổ sung Sơ đồ phụ thuộc State & Data (State Dependency Graph)

  • Vấn đề: Dự án dùng Riverpod 3.x với nhiều Provider phụ thuộc lẫn nhau (app_providers, retrieval_providers, notebook_providers) và    
  3 cơ sở dữ liệu SQLite (app.db, user_data.db, notebook.db).
  • Gợi ý cải thiện: Bổ sung một sơ đồ ngắn (Mermaid hoặc ASCII) trong PROJECT_SUMMARY.md thể hiện luồng:
  UI ➔ Riverpod Provider ➔ Repository ➔ SQLite Store
  • Tác dụng: AI nhìn vào sơ đồ sẽ không bao giờ quên việc phải invalidate provider nào sau khi cập nhật dữ liệu, tránh lỗi UI không     
  tự refresh.
  ──────
  ### 2. Thêm quy định "Không ghi dữ liệu nhạy cảm vào Git" (Security Policy)

  • Vấn đề: Dự án có tích hợp Google OAuth, OpenRouter, DeepSeek API Keys.
  • Gợi ý cải thiện: Thêm 1 dòng nhắc nhở ngắn vào CLAUDE.md:
  │ 🔒 Security Rules: Tuyệt đối không bao giờ ghi API Key, Client Secret hoặc Refresh Token vào bất kỳ file code, mock test hay tài     
  │ liệu markdown nào bị Git theo dõi. API Keys luôn qua flutter_secure_storage.
  ──────
  ### 3. Tạo Checklist kiểm thử nhanh (.claude/SMOKE_TEST_CHECKLIST.md)
  • Vấn đề: Trong Known Issues có mục "Run the manual smoke test on the release exe". Khi chuẩn bị release, người dùng hoặc AI phải tự   
  nhớ cần test những gì.
  • Gợi ý cải thiện: Tạo một file ngắn .claude/SMOKE_TEST_CHECKLIST.md gồm 5-7 bước kiểm tra nhanh bằng tay trước khi xuất bản file .    
  exe:
      [ ] Mở app .exe độc lập (không qua IDE).
      [ ] Tìm kiếm 1 từ khóa ➔ Xem chi tiết entry.
      [ ] Tạo 1 note mới trong Sổ tay kèm ảnh đính kèm.
      [ ] Tạo 1 Ticket ngày ➔ Hoàn tất ➔ Mở lại.
      [ ] Thử Export Backup zip ➔ Import lại xem app có yêu cầu Restart đúng luồng không.

  ### 4. Quy định nguyên tắc TDD (Viết test kèm tính năng)

  • Gợi ý cải thiện: Thêm quy tắc vào CLAUDE.md:

  │ test/ phủ case đó trước khi kết thúc session.
